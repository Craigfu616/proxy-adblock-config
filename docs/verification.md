# 第一版验证记录

日期：2026-11-17（Asia/Shanghai）。

## 环境与范围

- macOS，Mihomo Meta v1.19.33，使用本机已安装的内核启动独立测试进程。
- 测试使用临时目录、临时监听端口、本地 HTTP 服务和保留测试域名，没有修改运行中的客户端或系统代理。
- 上游广告列表从秋风公开地址实际下载。测试广告域名通过临时 hosts 指向本地服务，用于确认拒绝发生在规则层，没有访问广告服务器。
- 没有读取或上传个人节点、密码和订阅链接；代理路由验证使用本机不可用的测试 SOCKS 端口。

## 同日补充：Shadowrocket 的节点选择与 DNS

直连版显式设置系统 DNS、`dns-direct-fallback-proxy = false` 和 `private-ip-answer = true`，并补充了选中节点与 `PROXY` 策略之间的关系，以及可选的本地占位节点说明。参数依据 Shadowrocket 使用手册和配置维护者的示例核对；已检查配置文本。此补充仍未在 iPhone 上实测。

## 同日补充：手机附加模块与真正直连节点

- `shadowrocket/adblock.module` 静态检查通过：只有三条附加规则，不设置节点、DNS 或 `FINAL`。
- `clash/direct-node-provider.yaml` 通过 Mihomo v1.19.33 的实际提供器加载，API 返回名为「广告屏蔽」、类型为 `Direct` 的出站。
- 将测试策略组切到「广告屏蔽」后，原本交给代理出口的请求成功直达本地目标，无需本地 SOCKS 服务。
- 将同一组切到测试 SOCKS 节点后，该请求尝试使用代理，没有悄悄改走直连。此测试节点不可用，未验证真实境外代理。
- 两种出口选择下，普通直连、白名单放行、自定义广告拒绝和上游广告拒绝均符合预期。
- 测试使用临时端口、临时目录和本地目标，未改变用户的客户端或系统网络设置。

之前的占位说明已修正：`127.0.0.1:9` 不是直连节点。Shadowrocket 首页节点订阅能否承载真正 direct 出站尚未确认；其广告模块仅静态核对，未进行手机测试。完整支持边界见 [手机附加说明](mobile-addons.md)。
